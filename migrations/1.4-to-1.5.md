# Migration: schema_version 1.4 → 1.5

## WHAT changed

`hooks_installed` 的单一布尔值无法区分“脚本已复制”和“当前 agent 的 harness 真正在执行 hook”。1.5 将其替换为：

| 字段 | 类型 | 默认值 | 含义 |
|---|---|---|---|
| `guard_scripts_installed` | bool | 旧 `hooks_installed` 值 | guard 脚本是否存在 |
| `hooks_backend` | enum | `"claude-code"` 或 `"none"` | 实际执行 hook 的 harness |
| `hooks_enforced` | bool | 见下方 | 预测锁是否经过实际验证 |

删除 `hooks_installed`，`schema_version` 更新为 `"1.5"`，`skill_version` 更新为 `"0.2.0"`。

## WHY

Codex 不执行 `.claude/settings.json`。旧字段可能让 Codex 用户看到“预测锁已安装”，但真实状态只是把脚本复制到了磁盘。1.5 把物理存在、执行 backend 和强制状态分开，避免虚假的安全承诺。

## HOW (agent steps)

1. 解析真实数据目录：显式 `--dir` → `CHEAT_DATA_DIR` → `.cheat-content.json` → 当前目录。
2. 备份 `.cheat-state.json` 为 `.cheat-state.json.1.4.bak`；已存在则不覆盖。
3. 读取旧 `hooks_installed`：
   - `false` → 三个新字段为 `false / "none" / false`。
   - `true` 且当前是 Claude Code，且 Phase 4 hook 测试确认拦截成功 → `true / "claude-code" / true`。
   - `true` 但当前是 Codex、其他 agent 或无法验证 → `true / "none" / false`。
4. 删除 `hooks_installed`，写入三个新字段。
5. 写 `schema_version="1.5"`、`skill_version="0.2.0"`。
6. 重新读取 JSON，确认三个字段类型正确后报告完成。

Windows 可直接运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/cheat.ps1 --project C:\path\to\project migrate --agent codex
```

## Manual fallback

备份 state 后，将：

```json
"hooks_installed": true
```

改为（Codex / 未验证 harness）：

```json
"guard_scripts_installed": true,
"hooks_backend": "none",
"hooks_enforced": false
```

最后把 `schema_version` 改成 `"1.5"`、`skill_version` 改成 `"0.2.0"`。Claude Code 只有在预测锁测试实际通过后，才可把 backend/enforced 改成 `"claude-code"` / `true`。
